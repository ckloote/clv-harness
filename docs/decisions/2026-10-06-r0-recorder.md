# R0 recorder implementation choices

Date: 2026-10-06

Status: accepted for R0

This record explains the choices made while building the R0 recorder (`tools/raw_recorder/`). DESIGN.md §7.1, §7.2, §10, §13 and §14 now describe the result. The recorder has been exercised against local fakes and in a short live run on public endpoints. It has **not** yet been used to stream with a Novig read key, and none of the R0 gate questions are answered yet.

## Archive grouping and manifest journal

Taken literally, §7.1 put each REST request in its own file (`conn_id = request_id` named the file) and rewrote `manifest.json` on every seal. At the R0 poll cadences that means roughly 20,000 files a day, plus tens of gigabytes a day of manifest rewrites. Over a season, the rewrites alone would wear out flash storage.

The fix changes files and manifests. It does not change the evidence:

- **Files are per stream, not per request.** A file belongs to a *stream*: one WebSocket connection (`stream_id = conn_id`) or one REST poller. Each REST line still carries `conn_id = request_id`, and replay still associates every response with its request by ID, never by adjacency. The interleaved identical-body fixture checks this. File count now grows with streams × hours, not with games or polls: about 50–150 files per capture day, and about 150 a day over a full season.
- **The manifest is an append-only journal.** Each day directory has a `manifest.jsonl`, with one line per sealed file. Earlier manifest versions survive as prefixes of the journal, which meets the §7.1 rule to preserve them without keeping copies. `manifest.json` is now a view built from the journal when the day closes.

A database was considered for the raw layer and rejected. Sealed files keep byte-exact frames and a sha256 that never changes, which V0's `fact_snapshot` can cite. They also give about 10× compression and simple incremental backup with `rsync`. SQLite still arrives in V0, for normalized facts that point into the archive (§7.5).

## Segment lifecycle and crash behavior

The active segment is a plain `.jsonl.part`. It is flushed after every frame and fsynced every `r0.fsync_interval_s`, so a crash loses at most that interval. Sealing runs:
- every `r0.segment_max_s`
- at UTC midnight, so a segment never spans two date directories
- on SIGHUP, `raw-recorder seal`, or shutdown

A seal gzips the segment deterministically (fixed mtime, no embedded name), hashes it, appends the journal line, sets the file to 0444 and removes the `.part`. Sealing runs in a worker thread, so compression never stalls a WebSocket receive loop past Novig's Ping deadline.

A process killed mid-write leaves a `.part` behind. The next session seals it with `unclean_close`, drops any torn final line and records the byte count, then records `previous_session_unclean` with the original session ID. Sealing is idempotent across a crash between the journal append and the `.part` removal. A complete line that fails validation stops the seal rather than sealing damaged evidence. One recorder per archive is enforced with an flock; commands that write to the archive refuse to run beside `run`.

## Novig probe budget

The Novig docs (read 2026-10-06) say a `snapshot` costs the same as a `subscribe`: 16 tokens per market on `book` and 4 on `trades`, from a per-key `stream` bucket of 512 that refills at 4 per second. At the §10 cadence of 15 s, probing every book market would exceed the refill rate beyond about three markets. Several postseason games overlap in their capture windows.

The recorder therefore:
- probes only markets whose channel has been quiet for `stream.channel_probe_interval_s`, because recent channel messages are already admissible evidence (§7.2)
- never lets probes draw a local model of the bucket below `r0.stream_probe_reserve_fraction` of capacity, which keeps headroom for subscribes and reconnects
- archives each unaffordable probe as `probe_skipped`

A skipped probe is missing evidence that has been recorded, never an inferred "unchanged". The 15 s cadence itself is unchanged until R0/A1 measures how often channels are actually quiet.

## Key handling

A `trading::read` key cannot read key metadata: `GET /v3/keys/{id}` requires a management scope. So the recorder cannot positively confirm its own scope. It confirms the negative instead. A 200 from that route means a management key was loaded, and the recorder refuses to stream. A `trading` key and a `trading::read` key both get 403 there, so provisioning must create `trading::read`. The recorder contains no order code in any case. The private key is loaded only from a file that is not readable by group or other.

A WebSocket handshake refusal loses its response body in the client library. After a refusal, the recorder makes one signed REST request through the envelope so the refusal body (a 451 JSON, or the edge's HTML 403) is still archived.

## Unsigned public data

Novig serves its catalog and order book without a signature under `/v3/public/...`, throttled per IP. The recorder uses the public catalog to choose markets, and archives each recorded market's catalog entry when its window opens. With no read key configured, it falls back to polling the public book every `r0.novig_public_book_poll_interval_s` (the response is cached for 5 s). That gives sequenced snapshots, not every change. It is a fallback, so a golden game can still be captured while a read key is pending. It does not replace the stream.

## Host and windows

R0 runs on the development machine; the long-term host is decided before A1, using R0's measured volumes. While any capture window is open, the recorder holds a systemd sleep inhibitor. A host that goes down anyway leaves a recorded gap, not corrupt evidence.

Windows default to 3 h before scheduled first pitch through 90 min after it (`r0.capture_lead_s`, `r0.capture_tail_s`), and either can be overridden per game. Odds polling runs from `r0.odds_window_lead_s` before scheduled first pitch until first pitch. At the 20-minute cadence, the remaining postseason should use about 350 of the 500 free monthly credits, and the credit floor protects the rest.

## Validation

`uv run pytest`: 109 tests passed on Python 3.12.13 (aiohttp 3.14.4, cryptography 50.0.2, NumPy 2.5.3, pytest 9.1.1). The suite includes:
- the 41 pre-existing calibration and specification tests
- all 30 Novig signing vectors
- the §7.1 R0 archive fixtures: interleaved identical-body REST requests, a timeout, an HTML 403, a quiet WebSocket market with control Pings and snapshot probes, reconnect, and budget-skipped probes
- seal, journal and verify tamper checks, orphan recovery and a refused second writer

A live 40-second run on 2026-10-06 against public Kalshi, Novig and StatsAPI endpoints sealed and verified cleanly. No Novig stream, Odds API call or full game has been captured yet.
