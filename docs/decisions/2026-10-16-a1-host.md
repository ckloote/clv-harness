# A1 host: a Raspberry Pi running the recorder only

Date: 2026-10-16

Status: accepted. It settles open decision 2 of `2026-10-16-a1-scope.md`, and supersedes the single-host arrangement of `2026-10-08-single-host-provisioning.md` for the recorder.

## Context

Gate A1's 48 hours continuous cannot run on the development workstation, which suspends (`2026-10-06-r0-recorder.md`). Novig throttles per key, so one key must have one recorder: two processes would starve each other's `stream` bucket. R0 is still recording the MLB postseason on the workstation.

## Decision

**The host is a Raspberry Pi 5 (8 GB)** on wired Ethernet at the same home address as the workstation. That address already passes Novig's IP and companion checks.
- **The OS** boots from the 256 GB SD card.
- **The archive** is on a 1 TB Samsung T5 SSD on a USB 3 port.

**The Pi runs the recorder and nothing else.**
- **Installation:** `uv sync --package raw-recorder` only.
- **Not on the Pi:** `clv` ingest and calibration, and `raw-recorder backfill`, whose fetcher peaked at 6 GB in B1.
- **The workstation does all derived work,** from a mirror of the Pi's archive.

**No timestamp before the clock is synchronized.** The Pi 5 has a real-time clock, but without its optional battery it loses the time on a power cut and boots with the wrong time. A battery helps, and the rule below applies either way.
- **The unit** is ordered `After=time-sync.target` with `systemd-time-wait-sync` enabled.
- **The recorder refuses to open a capture window while the clock is unsynced** (`clock_status()`), and archives `clock_unsynced`. A wrong clock becomes a recorded gap, never bad `recv_ts_ms`.

**Storage.**
- **The archive root** is on the SSD: ext4, mounted by UUID with `nofail`, never on the SD card.
- **Formatting:** the T5 ships formatted exFAT. Reformat it to ext4 before use, which erases it.
- **Power:** the official 27 W (5 V, 5 A) supply. With a lesser supply, the Pi 5 limits its USB ports to 600 mA in total, which a bus-powered SSD can exceed under write load.
- **USB resets:** if the kernel log shows UAS resets for the T5, add a `usb-storage.quirks` entry for its USB ID.
- **Capacity:** 1 TB, to be checked against the storage pilot's measured volume. `r0.min_free_disk_mb` alerts stay.

**The mirror is the backup and the ingest source.**
- **How it runs:** a systemd timer on the workstation runs `deploy/archive-mirror.sh` every 15 minutes. It rsyncs sealed segments and journals from the Pi, never `*.part` files.
- **Ownership:** the Pi's archive is authoritative, and the mirror is written only by rsync.
- **On ingest,** segment hashes are checked against the manifests, as now.
- **The mirror proves it is complete** (amended 2026-10-16 after the PR #26 review). Elapsed time is not evidence: a lagging or stalled mirror would let `clv ingest` load an event from part of its data and then skip it for good.
  - **The recorder** writes a seal watermark, `sealed_through.json`, every 30 s and on close. Every frame in the archive received before that time is in a sealed, journalled segment.
  - **A crashed session's unsealed parts hold it back** until a recorder start seals them. This applies to any writer, including a short command such as `catalog` run after the crash.
  - **The mirror** copies a snapshot of the watermark first, then the data, and publishes the snapshot last. A failed run publishes nothing new.
  - **`clv ingest`** loads a league event only once the mirror's watermark is past the end of its window.

**Keys.**
- **The Pi receives only the `trading::read` key,** as a 0600 file named by `NOVIG_READ_KEY_PATH`.
- **The management key never goes on the Pi.** Any provisioning happens on the workstation (`2026-10-08-single-host-provisioning.md`, Unchanged).

**Cutover after the World Series.** R0 stays on the workstation through the postseason. A1 is built and tested on the workstation against R0 archives and fixtures. When the postseason ends:
1. seed the Pi's archive with the workstation's;
2. stop the workstation's recorder;
3. start the Pi's.

One archive root then carries R0 and A1, with one key and one process.

## Consequences

- **`deploy/` gains:**
  - a Pi variant of `raw-recorder.service`, with time-sync ordering and the archive on the SSD;
  - `archive-mirror.service` and `archive-mirror.timer` for the workstation.
- **Restore test before the pilot:** ingest 849832 from the mirror into a scratch database, and match its golden trace.
- **A power cut costs only data.** A process kill or power loss is already handled by `recover_orphans` and the `unclean_close` journal. A UPS is optional.

## Amendment, 2026-10-17: the deployment files (PR 7)

`deploy/pi-host.md` is the runbook. Four choices go beyond the decision above:

- **The Pi's recorder is a system unit,** running as a dedicated `recorder` account (`deploy/raw-recorder-pi.service`). A user manager cannot order a unit after the system's `time-sync.target`, or keep it down until the SSD is mounted (`RequiresMountsFor`).
- **The archive root reaches the SSD by a link.** The checkout's `archive/` links to `/mnt/ssd/archive`, so the committed `config.toml` serves both hosts, and commands run by hand never write to the SD card. The empty mount point is made immutable, so nothing lands on the SD card when the SSD is missing.
- **The mirror reads through a restricted key.** The Pi forces the workstation's key to `rrsync -ro` on the archive root, so the workstation can read the archive but never write to it.
- **The cutover seeds twice.** A bulk copy runs while R0 still records. Then the workstation recorder stops, which seals everything, and a final pass copies the rest. The Pi's recorder starts only after `raw-recorder verify` passes on its copy. NBA is enabled only after the workstation recorder has stopped.
